# HypnoLoop 首版设计草案

日期：2026-10-04。用户选择 Flutter 并授权开始执行；首版 Android 功能、测试和 APK 离线构建已实现。本文与源码已保存在本地 Git 功能分支，实际验证边界见 [验证记录](../../validation.md)。

## 已确认的目的与范围

用户希望开发自娱自乐的动漫风格催眠视觉工具。第一阶段在 Android 手机上使用，之后适配 iOS 手机，最后适配电脑。首版是纯螺旋／爱心的全屏工具。

借鉴 [Stand404/HypnosisAPP-New](https://github.com/Stand404/HypnosisAPP-New) 的 Flutter 方案和动画思路。用户要求复用本机已有 Android 构建环境，先检查兼容性，仅下载实际缺少的组件；构建输出和工具不进入 Git，不修改 minimal-sleep 源码。

以下交互、参数和默认值为本次授权实施的依据。

## 技术路线与选择

推荐精简的 Flutter 应用：共享 Dart 绘制和界面代码，Android 优先验证，后续扩展 iOS 和桌面平台；现有 JDK、Android SDK、Gradle 和依赖缓存继续使用。

已比较整体改造参考项目、原生 Kotlin／Compose、Kotlin Multiplatform／Compose 与精简 Flutter 项目。Kotlin Multiplatform 同样支持共享 Android、iOS 和桌面界面；用户在比较后选择 Flutter。整体参考项目的无关功能、作者本地 Wrapper 地址和签名配置不纳入首版。

构建核验和差异详见 [开发环境核验](../../development-setup.md)。首版固定 Flutter 3.41.5，官方提交为 `2c9eb20739dfec95e2c74bd3dfa4601b0a8a36aa`，最低 Android API 24。该版本的构建校验接受现有 Gradle 8.13、JDK 17、AGP 8.13.2 和 Kotlin 2.3.21，最终兼容性仍以真实构建为准。当前 Flutter 3.47.5 要求至少 Gradle 8.14，故本阶段不采用，以免升级已有工具。Flutter 后续版本升级作为独立维护工作。

## 第一版的使用流程

打开应用后显示动画预览与控制面板。用户选择“螺旋”或“爱心”，调节参数，点击“全屏播放”。全屏时隐藏应用控件，单击画面显示一个包含暂停、设置和退出全屏的小工具栏。三秒无操作后工具栏隐藏；打开设置时不自动隐藏。

安卓返回操作先关闭设置，再退出全屏，再遵循正常应用返回行为。提供明确的可见退出按钮，保留系统返回手势。切换到后台时停止动画更新，返回前台后恢复离开前的播放／暂停状态，不把后台时间计入动画时钟。

横竖屏跟随设备，在屏幕尺寸变化后重新计算绘制范围。控制面板可滚动，按钮与调节项避开系统栏和挖孔区域。

## 动画与参数

螺旋是从中心铺满画布的旋转条纹。爱心先采用从中心不断向外扩散、交替着色的嵌套爱心，匹配参考项目。螺旋中心可以选择显示一个小爱心，默认关闭。

| 项目 | 参数建议 | 默认值 |
| --- | --- | --- |
| 两种动画共用 | 速度 0.1–2.0 倍、背景与前景颜色 | 0.5 倍；默认进入螺旋 |
| 螺旋 | 顺／逆时针、条纹数 2–8、疏密 1–5 | 顺时针、4 条、疏密 3 |
| 爱心 | 扩散间隔 0.4–2.0 秒、两种交替颜色 | 1.0 秒、粉色与深紫 |
| 螺旋中心爱心 | 显示开关、大小 5%–20% 短边 | 关闭、开启时 10% |

速度的基准明确为：1 倍时螺旋每 12 秒旋转一周，爱心从中心扩散到覆盖画布对角线半径用 4 秒。爱心扩散间隔按动画时间计，因此速度变化同时影响扩散和生成节奏；暂停时两者都停止。

提供三个内置配色：黑白螺旋、紫黑螺旋、粉紫爱心。配色只是可一键应用的默认参数，仍可单独调节。暂停是独立操作，速度参数不使用零值，以免扩散间隔除零。

首版保存最后一次参数；不增加自定义预设管理、图片上传、文件导入导出、文字、音频、摆钟、角色或剧情。这些功能均留给后续明确需求。

## 绘制与模块边界

采用 Flutter CustomPainter 绘制，由统一的动画时钟提供经过时间。旋转和扩散均按时间计算，与设备刷新率无关；暂停／恢复保持相位连续，改变速度不会突然跳帧。画布按当前尺寸计算覆盖半径，不沿用参考项目仅在初始化时缓存屏幕尺寸的方式。

模块保持简单：

- 设置模型：动画种类、参数、内置配色和校验规则，不依赖 Android 类。
- 绘制层：螺旋与爱心各一个绘制器，只接收尺寸、动画时间和已校验参数。
- 播放控制：播放、暂停、前后台状态和速度变化，使用单调时间。
- 界面：预览／播放器页面与设置面板，首版使用简体中文。
- 设置存储：本地保存并加载最后参数，包含数据格式版本。
- 平台显示适配：全屏、系统栏和屏幕常亮，与绘制算法分开；后续桌面窗口行为在这一层扩展。

优先使用 Flutter 内置能力。持久化采用官方 `shared_preferences` 2.5.5 的 `SharedPreferencesAsync`，依赖解析结果写入 lockfile；屏幕常亮和 Android 系统栏通过一个小范围平台通道实现，不增加常亮插件。不为原参考项目的整套插件做预下载。

## 全屏策略

“全屏播放”的核心是画布覆盖可用屏幕并隐藏应用控件。支持的 Android 版本采用对应沉浸式方式，并在返回前台时重新应用显示状态。

Flutter 当前文档指出：目标 API 36 及以上时，系统忽略传统 SystemUiMode.immersiveSticky 等模式，不能仅调用该枚举就承诺完全隐藏系统栏。实施时需按选定 Flutter 版本和 Android 设备验证；若 Flutter 系统栏入口不能满足要求，评估小范围 Android 原生窗口适配。在验证前，不降低 targetSdk 来掩盖问题。所有退出控件保持在安全区域内。

出处：[Flutter SystemUiMode](https://api.flutter.dev/flutter/services/SystemUiMode.html)。

播放时保持屏幕常亮；暂停、后台和离开播放器时解除常亮请求。使用持续变化的动画，不设计频闪效果。

## 存储与异常处理

设置保存在本机，无账号或后端。滑块变化立即更新预览，持久化采用防抖写入，结束拖动时保存最终值；不在每帧写磁盘。

缺少设置时使用默认值；字段非法时按对应参数默认值恢复，超范围数值限制在允许范围内；无法识别的数据格式使用默认配置。存储失败时保持内存中的当前设置，并显示简短的“设置未能保存”提示，播放仍可继续。

## 验收方式

1. Android 上两种动画都能启动，调参立即生效，暂停与恢复没有明显位置跳变。
2. 同样参数在不同刷新率下保持相同的运动速度；横竖屏旋转后没有空白区域。
3. 单击呼出工具栏、设置、退出按钮和系统返回顺序正确；背景／前台切换没有继续占用动画更新。
4. 重启应用后恢复最后参数；损坏的设置不会导致启动失败。
5. 对参数恢复、时间推进和暂停／恢复做有意义的单元验证，对主要播放操作做界面验证。
6. 真实 Android 项目通过 Dart 分析、Flutter 测试、Android Lint 和 debug APK 构建；在工具／缓存缺项补齐后重新执行离线构建。运行结果如有平台限制，记录实际证据。
7. 真机性能验收以 profile／release 模式进行，先以 60Hz 设备稳定播放为目标；完成实际测量后报告帧耗时，不将目标写成已实现事实。
